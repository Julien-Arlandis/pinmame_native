tilt_web — Documentation API

tilt_web est un bundle JS auto-suffisant (généré par node/bundle.js à partir de node/runtime.js + node/runtime-audio.js + le moteur WASM PinMAME) exécutable :

  • dans le navigateur, comme Web Worker (chargé par web/interface.js) ;
  • dans Node.js, via require('./tilt_web') qui expose { createEmulator } (utilisé par node/main.js / tilt_node).

Dans les deux cas, l'émulateur ne parle qu'un seul protocole texte ligne par ligne ({ channel, line }), plus un canal binaire séparé pour l'audio. Ce document liste l'intégralité de cette surface : la fonction exposée, les lignes de protocole (entrées/sorties), les canaux binaires, et la manière de brancher une fonction sur chaque type d'événement (changement de switch, sortie transistor/solénoïde, lampe, affichage, audio).

1. createEmulator(options)

Point d'entrée unique du bundle. Définie dans node/runtime.js.

function createEmulator({ sendLine, sendAudio, sendCapture, sendScope, loadRom })
  → { sendMessage(type, payload), handleLine(line) }
Option (callback fourni par l'hôte)Rôle
sendLine(channel, line)Appelée par le moteur pour émettre une ligne de protocole (!set:, !lamp:, !display:, @status:, …). channel est indicatif ('driver', 'display', 'status') — la donnée utile est toujours dans line.
sendAudio(left, right)Appelée à chaque bloc audio généré. left/right sont des Float32Array (mêmes longueur, échantillons [-1, 1], 44100 Hz).
sendCapture(d)Appelée pour la capture des bus son bruts (debug). d = { ym_L, ym_R, dac } (Float32Array).
sendScope(d)Appelée quand l'oscilloscope est actif. d = { ym_L, ym_R, dac, spk_L, spk_R }.
loadRom(romName, baseUrl)Doit retourner une Promise<ArrayBuffer> contenant le .zip de la ROM.

L'objet retourné expose deux méthodes — c'est toute la surface de contrôle du moteur :

MéthodeUsage
sendMessage(type, payload) Un seul type supporté : 'INIT_ENGINE' avec payload = { customRomBytes, customRomName, baseUrl }. Démarre le moteur WASM et charge la ROM.
handleLine(line) Transmet une ligne de protocole entrante (host → moteur) — voir §3.

2. Transport — Worker vs Node vs BLE/WebSocket

Le protocole ligne-à-ligne ne dépend pas du transport. web/interface.js sait parler à trois types de "maîtres" (master), tous exposant la même interface (SerialMaster, §6) :

TransportFonction de créationDétail
Worker local (navigateur)createWorkerPort()Fetch tilt_web, extrait le WASM embarqué, lance un Worker. Audio via postMessage({channel:'audio'}).
WebSocket (Node distant)createWebSocketPort(ws, name) / trySerialMaster(url)Se connecte à tilt_node (serveur intégré, port 8765 par défaut). Handshake : @master:name=….
Bluetooth LEcreateBlePort(device)Service UUID ab120001-…, caractéristiques OUT (notify) / IN (write). Fragmentation 511 octets, 1er octet = flag de fin (0x01) / suite (0x00).

3. Lignes entrantes — host → émulateur (@…)

Envoyées via master.send(line) (navigateur) ou écrites sur le WebSocket/BLE côté tilt_node, puis transmises à emulator.handleLine(line).

LigneParamètresEffet
@set:id=<n>&state=<0|1>id = n° switch (0-79), stateChangement d'état d'un switch/contact — écrit l'octet dans la mémoire WASM lue par le jeu.
@dip:id=<n>&state=<0|1>id = n° dip-switchChange un dip-switch.
@sound:cmd=<n>cmd = commande son (0-255)Injecte une commande sonore directement (bypass CPU).
@audio:distance=<n>&chip=<f>&dac=<f>&sep=<0|1>tous optionnelsRéglages mix audio (distance simulateur, balance chip/DAC, séparation stéréo).
@scope:on=<0|1>Active/désactive l'envoi du canal scope.
@capture:action=start|stopDémarre/arrête la capture brute des bus son.
@connect:input=1&display=1&driver=1(géré côté tilt_node, pas par handleLine)Annonce de connexion d'un client ; déclenche le renvoi de la liste de ROMs + derniers états connus.
@reboot:(idem, côté tilt_node)Recrée intégralement l'émulateur (reboot dur).
@rom:name=<n>&data=<base64>(idem, côté tilt_node)Change/injecte une ROM puis reboot.

4. Lignes sortantes — émulateur → host (!… / @…)

Reçues via le callback sendLine(channel, line) côté hôte, redistribuées par master.onMessage(cb) côté navigateur.

LigneParamètresÉvénement représenté
!set:id=<n>&state=<0|1> id = n° solénoïde/transistor (0-31) Changement de sortie transistor / solénoïde. Émise uniquement sur changement d'état (32 bits comparés à l'état précédent).
!lamp:<24 car. hex> 12 octets (colonnes) × 8 lampes État complet de la matrice de lampes (96 lampes), renvoyé en bloc à chaque frame modifiée.
!display:action=raw&data=<hex> 40 caractères VFD encodés en hex (16 bits/caractère) Contenu brut de l'afficheur.
!display:action=text&data=<urlencoded> texte ASCII Contenu de l'afficheur en texte (utilisé notamment pour la sortie série display).
@status:state=loading|ready&rom=<nom> Cycle de vie du moteur (chargement / ROM prête).
@machine:cpu=…|snd=…|stereo=0|1|rate=… Infos machine détectées (CPU, puces son, stéréo, fréquence).
@sound:chips=<liste> Liste des puces son actives (compatibilité Node).
@roms:list=<a,b,c> noms encodés URL, séparés par virgule Liste des ROMs disponibles côté serveur (tilt_node).
@audio:cmd=0x<hex> Log d'une commande audio reçue par le moteur son (diagnostic).

5. Canal audio (binaire, séparé du texte)

L'audio ne passe jamais par les lignes texte : c'est un canal dédié pour éviter la latence/charge du parsing. Le moteur appelle sendAudio(left, right) à intervalle régulier (pacing géré par node/runtime-audio.js / audio.startPacing()).

  • Worker (navigateur) : worker.postMessage({ channel: 'audio', left, right }) → côté interface.js, port.onAudio(cb).
  • Node (tilt_node) : converti en PCM 16-bit stéréo (floatTo16BitPCM) puis écrit dans le sink choisi (haut-parleur via play/aplay, ou fichier --audio-out).

7. Classe SerialMaster (API haut niveau, navigateur)

Définie dans web/interface.js. Enveloppe un transport (Worker / WebSocket / BLE) derrière une API unique — c'est l'objet que manipule le reste de l'interface (master.send(...), etc.).

MéthodeSignatureRôle
sendsend(line: string)Envoie une ligne @… vers l'émulateur (switch, dip, etc.).
onMessageonMessage(cb: (line: string) => void)S'abonne à toutes les lignes texte sortantes (!set:, !lamp:, !display:, @status:, …). Plusieurs abonnés possibles (liste interne).
onAudioonAudio(cb: (left: Float32Array, right: Float32Array) => void)S'abonne au flux audio PCM flottant.
onCaptureonCapture(cb: (d) => void)S'abonne au canal de capture brute.
onScopeonScope(cb: (d) => void)S'abonne au flux oscilloscope.
onDisconnectonDisconnect(cb: () => void)Appelé à la fermeture du transport.
namegetterNom du maître connecté.

8. Recettes — brancher une fonction sur un événement

Détecter un changement de switch (entrée)

Les switches sont des entrées envoyées par l'hôte vers l'émulateur — il n'y a pas d'« événement switch » émis par le moteur ; c'est vous qui le déclenchez (bouton UI, capteur physique, etc.).
// Faire passer le switch n°27 (pièce) à l'état "actif"
master.send('@set:id=27&state=1');
// ... puis relâché
master.send('@set:id=27&state=0');

Écouter les sorties transistor / solénoïde

master.onMessage((line) => {
    if (!line.startsWith('!set:')) return;
    const p = new URLSearchParams(line.slice(5));
    const id    = parseInt(p.get('id'));    // 0-31
    const state = parseInt(p.get('state')); // 0 ou 1
    console.log(`Solénoïde ${id} → ${state ? 'ON' : 'OFF'}`);
});

Écouter les lampes

master.onMessage((line) => {
    if (!line.startsWith('!lamp:')) return;
    const hex = line.slice(6);
    for (let col = 0; col < 12; col++) {
        const mask = parseInt(hex.slice(col * 2, col * 2 + 2), 16);
        for (let row = 0; row < 8; row++) {
            const lampId = col * 8 + row;
            const state  = (mask >> row) & 1;
            // ... réagir au changement
        }
    }
});

Écouter l'affichage (VFD)

master.onMessage((line) => {
    if (line.startsWith('!display:action=text&data=')) {
        const text = decodeURIComponent(line.slice(26));
        console.log('Affichage :', text);
    }
});

Récupérer la sortie audio

master.onAudio((left, right) => {
    // left/right : Float32Array, 44100 Hz, valeurs [-1, 1]
    monAudioContext_feed(left, right);
});

Suivre le cycle de vie du moteur

master.onMessage((line) => {
    if (!line.startsWith('@status:')) return;
    const state = new URLSearchParams(line.slice(8)).get('state');
    if (state === 'ready') console.log('Moteur prêt');
});

Côté Node.js — utiliser createEmulator directement

const { createEmulator } = require('./tilt_web');

const emulator = createEmulator({
    sendLine(channel, line) {
        if (line.startsWith('!set:'))   { /* sortie transistor */ }
        if (line.startsWith('!lamp:'))  { /* lampes */ }
        if (line.startsWith('@status:')) { /* cycle de vie */ }
    },
    sendAudio(left, right) { /* PCM flottant 44100 Hz */ },
    loadRom: (name) => require('fs').promises.readFile(`./roms/${name}.zip`)
});

emulator.sendMessage('INIT_ENGINE', { customRomName: 'bonebstr' });

// Simuler un appui sur un switch
emulator.handleLine('@set:id=27&state=1');

Référence du protocole texte : commentaire en tête de web/interface.js ; implémentation moteur : node/runtime.js (fonction createEmulator + handleLine) ; audio : node/runtime-audio.js ; assemblage du bundle : node/bundle.js.
